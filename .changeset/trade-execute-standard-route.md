`trade execute`: add an opt-in broadcast route for swaps. Set `NANSEN_TRADING_EXECUTION_ROUTE=standard` to broadcast a swap through the execution endpoint that tracks the on-chain outcome server-side; any other value than `standard` or `legacy` is rejected rather than silently falling back. On this route the command opts into the server-side pre-broadcast simulation, which the endpoint leaves off by default, so a transaction that would revert still does not reach the network. It also surfaces the aggregator's own revert reason alongside the backend's failure code, refuses a duplicate submission of a quote that is already in flight, refuses to broadcast at all if the quote carries no backend quote id (the key that lock is held on) rather than submitting without the protection the route advertises, stops at a failed swap instead of signing the next candidate quote (the backend keeps the quote claimed once a transaction hash exists, so the next candidate could only be rejected),, fails closed if the endpoint reports success without a transaction hash (there is nothing to verify, and on Solana nothing downstream fills it in), hands the local quote claim back when the endpoint says it never broadcast — an explicit no-hash failure, or a definitive 4xx rejection — so a fully-rejected run does not strand a quote that is still good, and no longer prints the `Broadcaster:` line (the route does not report one). A WalletConnect wallet that broadcasts the swap itself never reaches this endpoint — the command now says so and applies the same stop-at-a-failed-swap rule there, both when the transaction reverts and when the wallet returns no hash at all (which may mean it broadcast anyway), rather than prompting for the next candidate. The default route is unchanged, so behaviour is identical unless you opt in.
