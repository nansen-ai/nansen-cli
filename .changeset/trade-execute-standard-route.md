`trade execute`: add an opt-in broadcast route for swaps. Set `NANSEN_TRADING_EXECUTION_ROUTE=standard` to broadcast a swap through the execution endpoint that tracks the on-chain outcome server-side; any other value than `standard` or `legacy` is rejected rather than silently falling back. On this route the command surfaces the aggregator's own revert reason alongside the backend's failure code, refuses a duplicate submission of a quote that is already in flight, stops at a failed swap instead of signing the next candidate quote (the backend keeps the quote claimed once a transaction hash exists, so the next candidate could only be rejected), and no longer prints the `Broadcaster:` line (the route does not report one). A WalletConnect wallet that broadcasts the swap itself never reaches this endpoint — the command now says so and applies the same stop-at-a-failed-swap rule there, both when the transaction reverts and when the wallet returns no hash at all (which may mean it broadcast anyway), rather than prompting for the next candidate. The default route is unchanged, so behaviour is identical unless you opt in.
