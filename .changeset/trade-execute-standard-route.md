`trade execute`: add an opt-in broadcast route for swaps. Set `NANSEN_TRADING_EXECUTION_ROUTE=standard` to broadcast a swap through the execution endpoint that tracks the on-chain outcome server-side; any value other than `standard` or `legacy` is rejected rather than silently falling back. On this route the command opts into the server-side pre-broadcast simulation, which the endpoint leaves off by default, so a transaction that would revert still does not reach the network. It also surfaces the aggregator's own revert reason alongside the backend's failure code, refuses a duplicate submission of a quote that is already in flight, refuses to broadcast at all if the quote carries no backend quote id (the key that lock is held on) rather than submitting without the protection the route advertises, stops at a failed swap instead of signing the next candidate quote (the backend keeps the quote claimed once a transaction hash exists, so the next candidate could only be rejected), fails closed if the endpoint reports success without a transaction hash or returns a body that is not this route's shape, reports a node-rejected broadcast on Solana as an unverified outcome rather than a successful swap (the EVM path resolves that case by polling for a receipt; Solana has no such poll), and no longer prints the `Broadcaster:` line, which this route does not report. A WalletConnect wallet that broadcasts the swap itself never reaches this endpoint — the command now says so, and applies the same stop-at-a-failed-swap rule there, both when the transaction reverts and when the wallet returns no hash at all, rather than prompting for the next candidate.

Gasless swaps stay on the default route: the standard route has no gasless envelope, so a signed Relay authorization sent there would lose its framing and submit as a plain swap.

The default route is unchanged. Without the environment variable no swap reaches the new endpoint, and the only difference on the default path is that the swap broadcast now carries an `x-trade-attempt-id` header so retries of one user attempt are not counted as separate executions.
