`trade execute`: never treat an unverified broadcast as "nothing was sent". The command retries the next candidate quote when one fails, which is only safe if every failure provably happened *before* the transaction left — and several responses were being read that way when they did not prove it. `executeTransaction` now reports a failure in exactly one of two ways: a definitive pre-broadcast rejection, which the status or the backend stated, or an ambiguous broadcast, which is the default for everything else and stops the command instead of signing another transaction. In particular: a response on a successful status that cannot be read (an empty body, an HTML page, or JSON that is not an object) is no longer read as a rejection; a `null` JSON body no longer throws while a field is read off it, which used to strand the quote claim on an error status and continue to the next candidate on a successful one; a definitive rejection now hands the local quote claim back, so a fully-rejected run does not leave a still-good quote unusable; an on-chain revert reports the revert itself rather than a generic "all quotes failed"; and a WalletConnect reply carrying neither a transaction hash nor signed bytes stops the command, because the wallet may already have broadcast. A failure thrown by the WalletConnect send itself now stops the command too: the underlying helper reports a user rejection, a 120-second approval timeout and a failure to launch the same way, so a timeout after the user approved — where the wallet did broadcast — could not be told apart from a transaction that never left, and the next candidate quote was signed on top of it. This now covers every WalletConnect send, not only the swap: a failed approval or allowance revoke also ends the command, because the next candidate would otherwise ask the wallet for a swap while the earlier approval was still in flight and the real allowance was unknown. More generally, any failure raised after a transaction has been handed to a wallet or to the backend now ends the command and marks the quote as spent, unless the failure is a definitive pre-broadcast rejection.
